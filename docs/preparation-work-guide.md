# 장비 도착 전 준비 작업 안내

NAS와 현장 장비가 없어도 진행할 수 있는 계약·목업·장애 재현·AAS 소비자·검수 보고서를 준비했다. 기존 v1.2 API·DB·아키텍처를 유지하며 장비 설치를 대신 완료했다고 기록하지 않는다. 현재 구현 DB는 PostgreSQL 17이고 일정 초안의 DynamoDB로 변경하지 않았다.

## 작업 순서와 문서

1. `producer-integration-contract.md`로 분석·녹화 담당자와 식별자·입력 경로·녹화 확정·중복 전달을 확인한다.
2. `producer-mock-guide.md`로 CCTV·로봇의 독립 입력과 합성 영상을 만든다. 같은 입력 재시험은 replay를 사용한다.
3. `fault-rehearsal-guide.md`로 로컬 장애 회귀와 개발 API 지연·유실을 재현한다. 기존 replication 시험에서 NAS·워커·lease·정리 경계를 함께 검증한다.
4. `aas-consumer-guide.md`로 외부 파트너와 같은 scope·자산 권한을 가진 읽기 클라이언트를 실행한다.
5. `acceptance-report-guide.md`로 AT01~AT25의 증거를 모으고 `acceptance-report-template.md`에 실제 환경 검수 결과를 기록한다.

## 일정에 적용

11월 16일 NAS 도착 전에는 합성 영상·계약 검토와 보고서 준비를 마칠 수 있다. NAS 도착 후에는 지원 파일시스템·볼륨 ID·마운트·0600 비밀 파일·수신기와 워커 실행 호스트·SSH·HTTPS 경로를 확정하고 실제 저장을 검수한다. NAS가 워커 실행을 지원하지 않으면 별도 사무실 PC에서 워커를 실행한다.

11월 23일 현장 연동에서는 목업을 실제 분석 프로그램으로 교체하고 같은 inbox 계약과 권한을 확인한다. 사무실과 독립된 현장→AWS 회선, 부분 전송·전원·ACK 유실 및 30일 사본 정리를 검수한다. 11월 30일에는 AAS 목업 결과와 실제 파트너 제품 검수를 비교한다. 12월 7일에는 누적 보고서에서 미검수·실패를 모으고 전체 부하·백업 복원과 RPO/RTO를 측정한다.

## 남은 외부 조건

실제 NAS와 CCTV·로봇·사무실 호스트 접속 정보, HTTPS 인증서와 네트워크 경로, 개발 계정의 현재 유효한 파트너·엣지 자격 증명, 담당자 간 계약 확인 및 실제 영상 코덱 검수가 필요하다. 예제의 siteId·assetId와 URL은 샘플이며 자동으로 권한을 만들지 않는다. 실시간 스트리밍·AI 모델·로봇 제어·알림 발송은 이번 구현 범위에 추가하지 않았다.

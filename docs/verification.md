## 공통 실행 로그 추가 검증

AOP 적용 후 전체 시험을 재실행했다. 동기·비동기 함수의 반환값·예외·시그니처 보존, generator 자원 정리, 중첩 span, 동시 요청·Lambda 실행 간 문맥 분리, executor 재사용 및 실제 lease 스레드의 문맥 전달을 확인했다. 로그 출력 실패가 업무 결과를 바꾸지 않고, DEBUG에서도 함수 인자·결과·예외 메시지·토큰·서명 URL·NAS 경로를 기록하지 않는지 검사했다.

API 성공·충돌·인증·입력 검증·크기 제한·미등록 경로·DB 장애·처리되지 않은 예외의 로그, 신규 비동기 경로의 자동 적용, outbox ACK·재시도·격리 및 클립 실패 상태 로그를 확인했다. 413 본문의 `traceId`도 응답 헤더와 같은 서버 추적 ID를 사용하도록 보완했다. OpenAPI 계약의 변경은 없다. 실제 CloudWatch·현장 journal 수집 확인은 배포 환경 검수에 해당한다.

### v1.2 AWS 개발 실연동 결과

기존 `dsc-dev-app`을 갱신하고 스키마를 `952701c2d6ef`로 전환했다. 기존 데이터의 건수와 이벤트·자산·영상 메타데이터 해시가 전후 일치했다. 실제 Cognito·API Gateway·Lambda·PostgreSQL·SQS·S3로 사무실 주 업로드, NAS 비정상 시 로봇 예비 업로드, 사무실 실패 후 CCTV 재배정의 세 경로가 READY가 됐고 다운로드 바이트가 원본과 일치했다. 이전 lease의 완료 통지는 404로 거부했고 위조 siteId는 403, 같은 이벤트 재전송은 중복 확인 200이었다. 실제 API 발급 다운로드 URL도 만료 후 S3 403을 확인했다.

사무실 수신기는 로컬 ASGI 경계, NAS는 로컬 디렉터리를 사용했다. 따라서 실제 현장 WAN·TLS·NAS 파일시스템·정전·부하와 백업 복원은 추가 검수 대상이다. 아티팩트 해시, 요청 ID, 데이터 보존·시험 자원 정리와 남은 설치 조건은 [v1.2 개발 배포 기록](office-worker-deployment-v1.2.md)에 있다.
